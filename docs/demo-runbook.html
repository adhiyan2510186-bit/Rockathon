Procurement Agent Demo Runbook

One unbroken run through every feature, in the order that tells the story. Roughly eight minutes with the encores.

Main run ~6 min
Encores ~2 min
App localhost:8501

Before you stand up

Two minutes, done once, off-stage.

00

Set the stage

streamlit run app.py → open http://localhost:8501 Ctrl+Shift+R → force a fresh load

In the sidebar, open Demo controls and confirm only First payment attempt declines is ticked. Open Suppliers and confirm both are ticked. Then press New order.

Know this before you present Code edits reload automatically; theme changes do not. If you touch .streamlit/config.toml, restart the server or the light/dark switch will not move.

The main run

The story is: it knows what it is for, it reads a messy sentence, it explains itself, and it knows where its authority stops.

01

It knows what it is not for

Type into the box at the bottom: What's the weather in Chennai tomorrow?

It states its scope and stays ready. No order is started.

There is no “off-topic” button here — the check runs on whatever anyone types, from any screen. An agent that will answer anything will also buy anything.
02

One messy sentence in

Request tab → Recent requests → click the entry "5,000 kraft mailer boxes · max Rs 22/unit · within 10 days"

Stay on the Request tab and read the chips back. Requirements and preferences are shown separately.

Requirements decide who qualifies. Preferences decide who wins. Blurring those two is how an agent quietly rejects a product for being slightly imperfect.
03

Show that the model only reads

Open the drill-down: “How this was read”

The extracted fields, and where every weight came from.

This is the only place a language model touched anything. It turned English into these fields and then had no further say. Every number after this point is plain Python.
04

The recommendation

Recommendation tab

Corusafe DW, ₹1,09,500, the four figure tiles, then the red ! Order today chip with “about 3 days of cover left”.

It leads with the decision and the cost, not a table. And it is already telling her the timing is tight.
05

Why this one — the chart to slow down on

Scroll to “Why this one”

Point at the blue segment on the winner, then at its absence on EcoMail.

She said reliability matters. Blue is reliability — it is most of the winner’s bar and none of the cheapest option’s. The cheapest product here is twenty percent under her budget and it ranks last. The formula has no favourite. The brief does.
06

Open the arithmetic, because you can

Open: “Score breakdown — Corusafe DW (58.0)” Then: “Not considered (4)”

Four terms that sum to 58.0, then the rejected products with reasons.

Weight times value, four terms, checkable by hand. And we keep the rejections — “here are three products” is a claim; “we looked at seven, three qualified, here is why the other four did not” is a checkable one.
07

Market context

Scroll to “Market context”

Two charts. On the stock chart, trace the winner’s line down to the dotted “you need 5,000” rule.

Where that line crosses is a date. They hit zero in four days, but they can no longer fill her order in three. And note the label — this is simulated data and we say so.
08

The guardrail — your strongest thirty seconds

Approval tab

₹1,09,500 — ₹4,500 over the limit. Nothing has been ordered.

The agent found the best fit, flagged it as urgent, and still stopped to ask. Urgency changes priority. It never changes authority. An agent that can talk itself past its own spending limit by claiming something is urgent is exactly what we built this to rule out.
09

Approve, and let it fail once

Click: Approve this order

Supplier confirms → first payment declines → retry succeeds → order placed.

It re-checked the price with the supplier before paying — against the source, not against its own cached copy. Then the card declined, it retried once, and it closed. It did not retry forever.
10

The trail

Activity tab → open “The finance record” → open “Read it back from disk”

Every line was written the moment it happened, not assembled afterwards. An assumption logged after the purchase is just a story. And that is read back from the exported file — what a finance system would actually receive.

Encores

Pick one or two. Each needs a fresh order.

How to reset A completed order is final — the agent will not reopen one. Use Demo controls → Run this brief again. It starts a new order with a new reference and its own audit file, using whatever switches are set. That is deliberate: reopening a finished order to try a different ending would make the audit trail a lie.
Tick this switchThen approve, and it will…The line
Vendor is out of stock Escalate instead of quietly taking second place “Number one led by 9.3 points. That is a meaningfully worse fit, so a human decides.”
Price moved since we looked Catch it at confirmation — no money moves “It re-reads from source. Checking its own cached copy would pass every time.”
Every payment attempt declines Stop after one retry and escalate “Retrying forever is how one failed payment becomes forty.”

If you have more time

Four more beats, each a different part of the design.

It acts alone when it is allowed to

A smaller order sits inside the limit, so it buys without asking and tells her afterwards. This is the half people forget: the boundary has two sides.

1,000 kraft mailer boxes, double-wall, 200x150x80 mm, max Rs 22 per unit, delivered within 10 days. Reliability matters a lot.

Nothing qualifies

No product clears every requirement. It surfaces three near-misses with the exact gap, and proposes — never applies — a relaxation.

5,000 kraft mailer boxes, double-wall, 200x150x80 mm, max Rs 12 per unit, delivered within 3 days.

It asks one question, not twelve

An incomplete brief gets a single targeted question, and your fragment answer is joined to the brief it answers. Note: the scores differ, because this version never says reliability matters — the cheapest option wins instead. That contrast is worth pointing out.

I need some mailer boxes → then answer: 5,000 of them, double-wall, 200x150x80 mm, max Rs 22 each, within 10 days

Swap the suppliers out from under it

Untick BoxBazaar and run again. Same engine, different feed. The winner holds at 58.0, but the runner-up drops from 48.7 to 34.0 — because the pool it is compared against just shrank. The pool is the comparison.

Sidebar → Suppliers → untick BoxBazaar → Run this brief again

Things that will bite you

The golden numbers 58.0 / 48.7 / 33.7 only appear for the full brief. If you demo the clarifying-question path first, the scores will legitimately differ. Use the Recent requests entry for the numbers on your slide.
If the model rate-limits The free tier allows about ten requests a minute. If it trips, the app falls back to a deterministic parser and says so on screen. Do not hide it — say “we degrade honestly; we never fake a model call” and carry on. The ranking is unaffected either way.
If something breaks badly git checkout v1-demo-frozen is a known-good, tested build. Never delete that tag.

Dark mode

The options menu at the top right → Settings → Appearance. Worth a beat if someone asks about polish: it is a second validated palette, not an inversion — the same hues re-stepped for a dark surface, because a palette that clears every contrast gate on white will fail all of them on black if you just flip it.
